# FedPLoRA 20260712：NX0 主表补齐与 strict held-out cold-start 命令

######### FedPLoRA-v13a one-shot 主表补齐 + strict held-out 能力实验-20260712 #########

【命令介绍】

本文件分两部分：

1. 第一部分：模板式单实验命令。每个实验一条 `nohup`，每条命令独立 PID、独立 run log、独立 result log、独立 checkpoint/产物。
2. 第二部分：阶段流水脚本。pipeline 自己有独立 nohup 日志；同一级别实验并行启动，一个实验一个 nohup PID 和产物；阶段结束后根据 gate/阈值决定是否进入下一阶段。

smoke 与 pipeline 分开：先单独跑 smoke；pipeline 默认只检查 smoke 是否通过，不主动跑 smoke。

【命令目的】

两份 20260712 分析文档结论一致：当前不应新造 v14 或继续扫 μ/A 网格；最高信息价值是补合法 split42 的 v13a 主表，并修复 cold-start 的 A 泄漏。

本轮命令覆盖：

- P0：三 split benchmark fingerprint，防止 `/data2` 与 `/data` 同名异版再次混表。
- P0：`NX0_v13a_os_split42_train42`，完成 v13a 与 baseline 同协议的合法 3-split 主表。
- P2：`NX0_v13b_bonly_split42_train42`，补 9.49 MiB 通信归因点，可与 NX0_v13a 并行。
- P1：strict held-out cold-start split42，每域留 1 个 client 完全不参与 A/B 训练；报告域标签 oracle B pool 与 few-shot geometry route 两种变体。

```text
smoke check -> fingerprint 3 splits -> NX0(v13a + v13b 并行) -> NX0 gate -> strict held-out -> heldout gate
```

默认 gate：

```text
NX0_MIN_V13A_LOCAL=0.5980      # 是否继续 held-out 能力线的最低不崩阈值
NX0_MAIN_LOCAL_TARGET=0.6071   # split42 强主表目标，只写入 decision_hint，不阻断
HELDOUT_MIN_COLDSTART_DELTA=0.01  # held-out best transfer 至少比 global 高 1pt
```

# 命令之间的串行和并行逻辑

## A. 手工命令逻辑

```text
Smoke 阶段:
  smoke_v13a_os                 并行
  smoke_v13b_os_bonly           并行
  X2_strict_heldout_smoke       并行或单独跑

Fingerprint 阶段:
  三 split 指纹审计             0 GPU，可与 smoke 同时跑，但建议先看 preflight

NX0 阶段:
  NX0_v13a_os_split42_train42   P0，必跑
  NX0_v13b_bonly_split42_train42 P2，资源够与 v13a 并行

Held-out 阶段:
  X2_strict_heldout_seed42      建议 NX0_v13a 出数后跑
```

手工模式下，是否进入下一阶段由你人工查看日志/JSON 决定。

## B. pipeline 自动逻辑

```text
串行阶段 0:
  检查 smoke 日志。
  不运行 smoke。

串行阶段 1:
  fingerprint seed42/43/44。
  check_benchmark 必须 35 clients。
  输出:
    pipeline_root/fingerprints/seed_*.json
    pipeline_root/gates/fingerprint_gate.json

串行阶段 2:
  并行启动 NX0_v13a 与可选 NX0_v13b。
  每个实验一个 nohup PID:
    pipeline_root/pids/nx0_<method>_seed42.pid
  每个实验独立产物:
    result_logs/<method>/
    result_files/client_states/<method>/
    checkpoint/<method>_*
  wait 全部 NX0 PID。
  grep 日志错误。
  解析 v13a metrics。
  gate:
    v13a Local >= NX0_MIN_V13A_LOCAL
  gate 结果:
    pipeline_root/gates/nx0_gate.json

串行阶段 3:
  若 NX0 gate 通过，启动 strict held-out cold-start。
  held-out 设置:
    每域最小 client_id 留出 1 个，共 7 个 held-out clients。
    held-out clients 不参与 A_global / B_global / B_domain pool。
  wait held-out PID。
  grep 日志错误。
  解析 eval JSON。
  gate:
    max(coldstart, coldstart_geom, v11c_coldstart, select_without_local) - global >= HELDOUT_MIN_COLDSTART_DELTA
  gate 结果:
    pipeline_root/gates/heldout_gate.json
```
