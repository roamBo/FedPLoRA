# FedPLoRA one-shot v13 实验命令

######### FedPLoRA one-shot v13 主算法复核与阶段流水命令-20260711 #########

【命令介绍】

本文件分两部分：

1. 单实验 nohup 命令区：严格按模板风格，每个实验一条 `nohup` 命令；每条命令对应一个进程号、独立 run log、result log、client state 和 checkpoint。
2. 阶段流水脚本区：在文档末尾给出一个 pipeline nohup 命令。pipeline 本身有独立 nohup 日志；同一阶段内的实验并行启动，每个实验仍然是一个独立 nohup PID 和产物；阶段结束后做日志/指标 gate，达标才进入下一阶段。

注意：smoke 和正式流水分开。先单独跑 smoke；pipeline 默认只检查 smoke 是否通过，不主动跑 smoke。

【命令目的】

根据 `/Users/hawaiii/codex/FedPLoRA/codex/codex_Analysis_20260711_oneshot.md`，本轮优先验证：

- `fedplora_v13a_os`：主算法，等价于 `v11a_alpha100_noAreg`，即 true A-delta sketch + routed B，`alpha=1.0`，去 μ，去 A/B local regularizer。
- `fedplora_v13b_os_bonly`：低通信归因分支，等价于 v8 routed 的 one-shot/cached-A 通信修正版，只影响新分支，不改历史 v8。
- 最高优先级实验：NX1，即 v13a/v13b × split/train seed43/44，补齐与 baseline 可比的多 seed 协议。

# 第一部分：每个实验一个 nohup 命令

说明：下面每条 `nohup bash scripts/RunScripts/run_20260711_one_experiment.sh ... &` 都是一个独立实验进程。该脚本内部不再二次 nohup，而是写 PID 文件后 `exec python`，因此 `$!` / pid 文件 / python 进程是一一对应的。

# 命令之间的串行和并行逻辑

## A. 手工单实验命令逻辑

```text
Smoke 阶段:
  smoke_v13a_os          并行
  smoke_v13b_os_bonly    并行

NX1 阶段:
  NX1_v13a_os_split43_train43      并行
  NX1_v13b_bonly_split43_train43   并行
  NX1_v13a_os_split44_train44      并行
  NX1_v13b_bonly_split44_train44   并行

NX4 阶段:
  X2_v13_coldstart_select_seed42   并行
  X2_v13_coldstart_select_seed43   并行
  X2_v13_coldstart_select_seed44   并行

NX3 optional:
  NX3_v11a_alpha100_split42_train43      并行
  NX3_v11c_mu020_split42_train42         并行
  NX3_v11c_mu020_split42_train44         并行
```

手工模式下，是否进入下一阶段由你人工查看日志/指标决定。

## B. pipeline 自动逻辑

```text
串行阶段 0:
  检查 smoke 是否已存在且日志无 Traceback/OOM/error。
  不运行 smoke。

串行阶段 1:
  NX2 md5 audit。
  md5 不一致则停止。

串行阶段 2:
  并行启动 NX1 四个实验。
  每个实验一个 nohup PID:
    pipeline_root/pids/nx1_<method>_seed<seed>.pid
  每个实验独立产物:
    result_logs/<method>/
    result_files/client_states/<method>/
    checkpoint/<method>_*
  wait 全部 NX1 PID。
  grep 日志错误。
  解析 metrics json。
  gate:
    completed_runs >= NX1_MIN_COMPLETED_RUNS
    v13a seed43/44 local mean >= NX1_MIN_V13A_LOCAL
  gate 结果写入:
    pipeline_root/gates/nx1_gate.json

串行阶段 3:
  若 NX1 gate 通过，才并行启动 NX4 三个 eval。
  wait 全部 NX4 PID。
  grep 日志错误。
  检查至少 3 个 eval json 有效。
  gate 结果写入:
    pipeline_root/gates/nx4_gate.json

串行阶段 4 optional:
  若 RUN_NX3=1 且 NX1 gate 通过，才并行启动 NX3 三个 ablation。
  wait 全部 NX3 PID。
  grep 日志错误。
  检查至少 3 个 metrics json 有效。
```
